Wrapping pgvector as a LangChain Tool

In Lesson 1, we built a stateful LangGraph loop. But an agent is only useful if it can interact with the outside world. To do this, the agent uses Tools.

In this lesson, we will convert your obsidian_agent.document_chunks table (which has 53 chunks stored in PostgreSQL) into a retrieval tool that the LLM can query autonomously.

What is a LangChain Tool?

A LangChain Tool is a Python function that the LLM can decide to run. To make it a tool, we decorate it with the @tool decorator from langchain_core.tools. The decorator uses two key pieces of information:

  1. The Function Signature: Type hints (like query: str) tell the LLM what arguments to pass.
  2. The Function Docstring: The description tells the LLM when and why to use this tool. The LLM reads this description to make its decisions!

Step 1: The Vector Search Tool

We write a function that embeds the user's query and performs a similarity search in PostgreSQL using pgvector.sqlalchemy's cosine_distance. Here is how it looks:

from langchain_core.tools import tool
from langchain_huggingface import HuggingFaceEmbeddings
from src.ingestion.db import get_session
from src.ingestion.models import DocumentChunk

@tool
def search_textbook(query: str) -> str:
    """Useful for retrieving technical information about AI engineering, RAG, and evaluation metrics from the textbook database."""
    print(f"--- Running Tool: search_textbook for '{query}' ---")
    
    # 1. Generate query embedding
    embeddings = HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2")
    query_vector = embeddings.embed_query(query)
    
    # 2. Query pgvector in database
    with get_session() as session:
        results = (
            session.query(DocumentChunk)
            .order_by(DocumentChunk.embedding.cosine_distance(query_vector))
            .limit(3)
            .all()
        )
        
        # 3. Format results as a readable string
        docs = []
        for i, r in enumerate(results):
            docs.append(f"Result {i+1}:\n{r.content}\nMetadata: {r.metadata_}\n---")
        return "\n\n".join(docs)

Step 2: Binding Tools to the LLM

Once we have a tool, we need to let the LLM know about it. We do this by binding the tool to the LLM instance using llm.bind_tools([tool]). This tells the model what functions are available to call.

import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI

load_dotenv()

# Instantiate LLM pointing to OpenCode Go
llm = ChatOpenAI(
    base_url="https://opencode.ai/zen/go/v1",
    api_key=os.getenv("OPENCODE_API_KEY"),
    model="glm-5.2"
)

# Bind the tool to the LLM
llm_with_tools = llm.bind_tools([search_textbook])

Interactive Exercise

Let's run a script that lets our OpenCode Go model decide whether to call the vector search tool. We will create a script called run_tool_check.py.

  1. Create run_tool_check.py in your root directory.
  2. Add code to call the model with a question about RAG (which requires the textbook) vs a greeting (which does not): 
    # Example execution in run_tool_check.py
if __name__ == "__main__":
    # Test 1: Simple greeting (should NOT trigger tool call)
    response_greeting = llm_with_tools.invoke("Hi, how are you?")
    print("Greeting Tool Calls:", response_greeting.tool_calls)
    
    # Test 2: RAG question (SHOULD trigger tool call)
    response_rag = llm_with_tools.invoke("What are some evaluation metrics for RAG?")
    print("RAG Tool Calls:", response_rag.tool_calls)
  3. Run it: 
    python run_tool_check.py
